# Monster Forge: Build, Merge & Battle

เว็บสร้างมอนสเตอร์ผ่านไฟล์ JavaScript สำหรับเวิร์กช็อป Git & GitHub ใช้ HTML/CSS/JavaScript ธรรมดา ไม่มีการติดตั้ง dependency ไม่มี backend และไม่เรียกบริการภายนอก

## เปิดใช้งาน

ดับเบิลคลิก `index.html` ในโฟลเดอร์นี้ ไม่ต้องใช้ npm หรือเปิด server ใช้งานออฟไลน์ได้ แก้ไฟล์แล้วบันทึก จากนั้นรีเฟรชหน้าเว็บ หากยังเห็นข้อมูลเก่าให้กด Ctrl+Shift+R

## แก้มอนสเตอร์

- คน A แก้ `monsters/monster-a.js`
- คน B แก้ `monsters/monster-b.js`
- รอบบอส ทั้งคู่แก้ `monsters/boss.js`

เปลี่ยนชื่อ คำอธิบาย รูป แต้ม สกิล และติดตัวได้ในไฟล์ของคุณ อย่าเปลี่ยน ID หรือเครื่องหมายคำพูด จุลภาค และวงเล็บของ JavaScript ไฟล์แต่ละตัวถูกโหลดไว้แล้ว ไม่ต้องลงทะเบียนในไฟล์อื่น

```javascript
name: "ชื่อที่คุณตั้ง",
description: "นิสัยของมอนสเตอร์",
image: "assets/monster-a.svg",
skill: "strike",
trait: "berserk",
stats: {
  hp: 30,
  attack: 25,
  defense: 15,
  speed: 10,
  critical: 10,
  lifesteal: 10,
  evasion: 0,
  armorPierce: 0
}
```

ทั้ง 8 ค่ารวมกันมีงบ **สูงสุด 100 แต้ม** ใช้ไม่ครบยังต่อสู้ได้และเว็บบอกแต้มที่เหลือ ใส่เป็นตัวเลขโดยไม่ครอบด้วยเครื่องหมายคำพูด

| ค่าในไฟล์ | เพดาน | ผลในการต่อสู้ |
| --- | --- | --- |
| hp | 50 | เพิ่ม HP สูงสุด |
| attack | 40 | เพิ่มความเสียหาย |
| defense | 40 | ลดความเสียหายที่ได้รับ |
| speed | 40 | ตัวเร็วเริ่มก่อน และเพิ่มหลบเล็กน้อย |
| critical | 25 | โอกาสคริติคอลเป็น % แรง 1.5 เท่า |
| lifesteal | 20 | ฟื้นเลือดเป็น % จากดาเมจที่เข้า HP จริง |
| evasion | 20 | โอกาสหลบเป็น % รวมโบนัส SPD แล้วไม่เกิน 20% |
| armorPierce | 30 | มองข้าม DEF ของคู่ต่อสู้เป็น % |

### เว็บจำกัดค่าอย่างไร

1. ค่าติดลบลดเป็น 0 ทศนิยมปัดลง ค่าเกินเพดานลดลงเหลือเพดานรายค่า
2. หากผลรวมยังเกิน 100 ให้ลดทุกค่าตามสัดส่วนและกระจายเศษแต้มจนรวม 100 พอดี
3. การ์ดแสดงค่าที่ใช้จริงและคำเตือนว่าปรับอะไรบ้าง ระบบต่อสู้ตรวจและ cap อีกครั้ง ไม่ใช่จำกัดแค่ตัวเลขบนหน้าเว็บ
4. ไม่เขียนทับไฟล์ต้นฉบับ คุณต้องแก้และ Commit ไฟล์เองสำหรับเวิร์กช็อป
5. ค่า string, null, NaN, Infinity หรือ base stats ที่หายไปถือว่าผิดและต่อสู้ไม่ได้ ไฟล์เก่าที่ไม่มี 4 stats ใหม่ยังทำงาน โดยค่าใหม่เริ่มที่ 0

ตัวอย่าง `attack: 999` จะใช้ได้สูงสุด 40 และอาจลดลงอีกหากแต้มรวมเกิน 100 ค่าที่ใส่ไม่สามารถเพิ่มงบหรือเพดานสกิลได้

### เลือก skill หนึ่งอย่าง

สกิลทำงานทุกตาที่ 3 ของตัวเอง โดยตาฟื้นพลัง/สร้างโล่จะไม่โจมตี พลัง ระยะเวลา และความถี่กำหนดไว้ในระบบ ไม่รับตัวเลขพลังสกิลจากไฟล์มอนสเตอร์

| skill | ผล |
| --- | --- |
| strike | โจมตีแรง 1.6 เท่า |
| poison | โจมตี 0.8 เท่าและติดพิษ 3 ตาของเป้าหมาย ตาละ 4% HP สูงสุด พิษไม่ซ้อนชั้นและทะลุโล่ |
| heal | ฟื้น 18% HP สูงสุด แต่ไม่เกิน HP เต็ม |
| shield | เพิ่มโล่ 20% HP สูงสุด สะสมได้ไม่เกิน 25% โล่รับการโจมตีก่อน HP |

### เลือก trait หนึ่งอย่าง

| trait | ผล |
| --- | --- |
| none | ไม่มีติดตัว |
| thorns | สะท้อน 15% ของดาเมจที่เข้า HP จริง ไม่มีการสะท้อนวน และยังสะท้อนการโจมตีสุดท้ายได้ |
| regeneration | ฟื้น 3% HP สูงสุดต้นตาตัวเองหลังรับพิษ หากยังมีชีวิต |
| berserk | โจมตีแรงขึ้น 20% เมื่อ HP ไม่เกิน 35% |

ดูดเลือดและหนามไม่คิดจากดาเมจที่โล่รับหรือดาเมจเกิน HP ที่เหลือ หากพิษฆ่าก่อนลงมือ จะไม่มีการฮีลหรือโจมตีต่อ และหาก HP หมดทั้งคู่จากหนามจะเสมอ

ไอเดียจัดชุด: สายคริติคอล + strike/berserk, สายทน + heal/thorns, สายพิษ + poison/regeneration หรือสายโล่ + shield/thorns เปรียบเทียบผลด้วยคู่เดิมแล้วแก้แต้มและรีเฟรช

`monster-template.js` เป็นตัวอย่างอ้างอิง ไม่ได้โหลดเป็นมอนสเตอร์จริง ในเวิร์กช็อปให้ใช้ A/B ที่เตรียมไว้ หากผู้จัดต้องการเพิ่มตัวใหม่ภายหลัง ให้คัดลอก template เปลี่ยน ID ให้ไม่ซ้ำและเพิ่ม script tag ก่อน `js/battle.js` เพียงครั้งเดียวก่อนเริ่มกิจกรรม

## ใส่รูปของตัวเอง

1. นำ PNG, JPG, SVG หรือ WebP ใส่ `assets/`
2. ใช้ชื่อไฟล์เฉพาะคน เช่น `alice-fire-cat.png` เพื่อเลี่ยงไฟล์ซ้ำ
3. แก้เป็น `image: "assets/alice-fire-cat.png",`
4. บันทึกและรีเฟรช รูปหายหรืออ่านไม่ได้จะแสดงรูปสำรอง

ใช้เส้นทางภายใน `assets/` และชื่อไฟล์ตัวอักษรไทย/อังกฤษ ตัวเลข ขีดกลาง ขีดล่าง หรือช่องว่าง ไม่ใช้ URL ภายนอก ภาพ SVG เริ่มต้นวาดขึ้นสำหรับโปรเจกต์นี้ ไม่มีฟอนต์หรือภาพจากอินเทอร์เน็ต

## ลองต่อสู้

เลือกมอนสเตอร์สองตัวที่ไม่ซ้ำกันแล้วกด **เริ่มต่อสู้** ดู HP และบันทึกการโจมตีที่เปลี่ยนทุก 0.3 วินาที กด **ดูผลทันที** เพื่อข้ามการแสดงทีละตา **สู้ใหม่** เริ่มคู่เดิมด้วย HP เต็ม และ **ล้างสนาม** ยกเลิกการต่อสู้พร้อมล้างผลโดยไม่รีเฟรช

สูตรใน `js/battle.js`:

```text
HP สูงสุด = 80 + (hp × 3)
โอกาสหลบ = min(20, evasion + speed × 0.1) %
DEF ที่ใช้คิด = defense ของเป้าหมาย × (1 - armorPierce ของผู้โจมตี / 100)
ความเสียหาย = round((12 + attack × 0.8) × 50 / (50 + DEF ที่ใช้คิด) × ค่าสุ่ม 0.9–1.1 × ตัวคูณสกิล × ตัวคูณคริติคอล × ตัวคูณฮึดสู้)
```

ความเสียหายอย่างน้อย 1 ก่อนหักโล่เมื่อโจมตีโดน ความเสียหายในบันทึกไม่เกิน HP ที่เหลือ SPD เท่ากันสุ่มผู้เริ่ม จากนั้นสลับลงมือ HP อยู่ระหว่าง 0 กับ HP สูงสุดเสมอ และไม่แก้ค่าต้นฉบับในไฟล์ มอนสเตอร์ HP หมดแพ้ทันที จำกัด 100 ตา (1 ตา = หนึ่งการลงมือ รวมการหลบ ฮีล สร้างโล่ หรือตายจากพิษ) หากยังไม่จบถือว่าเสมอ

## ไฟล์ที่ผู้เรียนไม่ต้องแก้

`index.html`, `style.css`, `js/data.js`, `js/app.js`, `js/battle.js` และ `assets/placeholder.svg` ผู้เรียนแก้เฉพาะมอนสเตอร์ที่ได้รับมอบหมายและเพิ่มรูปของตัวเองได้

## เตรียมงานสำหรับผู้จัด

1. สร้าง GitHub repository วางไฟล์ในโฟลเดอร์นี้ให้ `index.html` อยู่ที่ root ของ repository และ push เวอร์ชันเริ่มต้น
2. เตรียม branch `develop` และให้ทั้งคู่มีสิทธิ์ push branch / เปิด PR / merge ตามรูปแบบห้องเรียน
3. ให้ผู้เรียนติดตั้ง Git และ VS Code พร้อมตั้งค่า Git name/email และเข้าสู่ระบบ GitHub ไว้ก่อน
4. ให้ทั้งคู่ clone repository เดียวกัน เช่น `git clone <URL ของ repository>` แล้วเปิดโฟลเดอร์ที่ clone ใน VS Code ใช้ Terminal ของ VS Code รันคำสั่งด้านล่าง
5. ตรวจว่า A/B แสดงในเว็บและบอสยังซ่อนอยู่ รอบแรกไม่ให้แก้ไฟล์ร่วมกัน รอบสองต้องเริ่มจาก commit เดียวกัน

คำสั่งด้านล่างใช้จาก root ของ repository หากเก็บเว็บไว้ในโฟลเดอร์ `monster-forge/` แทน root ให้เติม `monster-forge/` หน้าพาธในคำสั่ง `git add`

## รอบ 1 — สร้างมอนสเตอร์คนละไฟล์

ทั้งสองคนเริ่มจาก:

```bash
git switch develop
git pull --ff-only origin develop
```

คน A:

```bash
git switch -c feature/monster-a
# แก้ monsters/monster-a.js บันทึก แล้วเปิดเว็บตรวจแต้ม
git add monsters/monster-a.js
# หากมีรูปใหม่ ให้ git add assets/ชื่อรูปของคุณ.png ด้วย
git commit -m "Create monster A"
git push -u origin feature/monster-a
```

คน B ทำเช่นเดียวกัน แต่ใช้ `feature/monster-b`, ไฟล์ `monsters/monster-b.js` และข้อความ commit ของตัวเอง

บน GitHub เลือก **Compare & pull request** ตั้ง **base: develop** และ **compare: feature/monster-a** หรือ `feature/monster-b` ตรวจ Files changed ให้มีเฉพาะไฟล์ที่ตั้งใจแก้ จากนั้น **Create pull request** ให้เพื่อน review แล้ว **Merge pull request** และยืนยันการ merge

เมื่อ merge ทั้งสอง PR แล้ว ทุกคนรัน:

```bash
git switch develop
git pull --ff-only origin develop
```

เปิด `index.html` แล้วเลือกมอนสเตอร์ทั้งคู่มาต่อสู้ การแก้คนละไฟล์และใช้ชื่อรูปไม่ซ้ำช่วยให้รอบนี้ไม่มี Merge Conflict

## รอบ 2 — ออกแบบบอสร่วมกันและแก้ Conflict

**สำคัญ:** ทั้งคู่ต้องสร้าง branch จาก `develop` commit เดียวกันก่อนใคร merge รอบบอส ใช้ `git log -1 --oneline` เปรียบเทียบรหัส commit ให้ตรงกัน

```bash
git switch develop
git pull --ff-only origin develop
git log -1 --oneline
```

คน A รัน `git switch -c feature/boss-a` คน B รัน `git switch -c feature/boss-b`

ทั้งคู่เปิด **ไฟล์เดียวกัน** `monsters/boss.js` เปลี่ยน **บรรทัด `name` เดียวกัน** ให้เป็นชื่อที่ต่างกัน และตั้ง `enabled: true` อาจแก้คำอธิบาย รูป แต้ม สกิล หรือติดตัวเพิ่มได้ โดยตั้งใจแบ่งแต้มให้ครบ 100 ภายในเพดานเพื่อไม่ให้ถูก cap อย่าสร้างบอสสองไฟล์ และยังไม่ merge งานของอีกคนเข้ามา

คน A:

```bash
git add monsters/boss.js
git commit -m "Propose boss A"
git push -u origin feature/boss-a
```

คน B ใช้ข้อความ `Propose boss B` และ push ไป `feature/boss-b` ถ้ามีรูปใหม่ให้ add รูปด้วย

1. A เปิด PR เข้า `develop` และ merge ก่อน
2. B เปิด PR เข้า `develop` หลังจากนั้น GitHub จะแสดง Conflict เพราะแก้ชื่อบรรทัดเดียวกันจากต้นฉบับเดียวกัน
3. B ตรวจว่า commit งานตัวเองครบแล้ว จากนั้นรัน:

```bash
git switch develop
git pull --ff-only origin develop
git switch feature/boss-b
git merge develop
```

### แก้ใน VS Code

เปิด Source Control แล้วเลือก `monsters/boss.js` ใน Merge Changes หรือเปิดไฟล์โดยตรง จะเห็นส่วนลักษณะนี้:

```text
<<<<<<< HEAD
  name: "ชื่อที่ B เสนอ",
=======
  name: "ชื่อที่ A เสนอ",
>>>>>>> develop
```

ตกลงชื่อสุดท้ายกับเพื่อน แล้วแทนที่ทั้งส่วนด้วยบรรทัดเดียว เช่น:

```javascript
  name: "บอสที่เราสร้างด้วยกัน",
```

ใช้ **Accept Current Change** (งาน B) หรือ **Accept Incoming Change** (งานจาก develop/A) ได้ หรือพิมพ์ค่าที่ตกลงกันเอง อย่าใช้ Accept Both แล้วปล่อยให้มี `name` ซ้ำ หากใช้ Merge Editor ให้กด Complete Merge เมื่อแก้ครบ

ตรวจว่าไม่มี `<<<<<<<`, `=======`, `>>>>>>>` หลงเหลือ มี `window.MONSTERS.push({...})` ของบอสเพียงชุดเดียว `enabled: true` ชื่อ รูป คำอธิบาย สกิล และติดตัวตรงตามที่ตกลง รวมแต้ม 100 ภายในเพดาน เปิดเว็บตรวจว่าบอสแสดงและต่อสู้ได้ แล้วรัน:

```bash
git add monsters/boss.js
git commit -m "Resolve shared boss conflict"
git push origin feature/boss-b
```

กลับไป PR เดิมของ B หน้า PR จะอัปเดตตาม push ใหม่ ให้ review และ merge จากนั้นทั้งคู่ switch ไป `develop` และ pull ล่าสุด บอสจะเป็นตัวเดียวที่ทุกคนใช้ร่วมกัน

## ตรวจสอบโปรเจกต์

ผู้ใช้เว็บไม่ต้องมี Node.js ผู้พัฒนาที่มี Node.js สามารถรันชุดทดสอบตรรกะโดยไม่ติดตั้งแพ็กเกจ:

```bash
node --test tests/core.test.cjs
```

ทดสอบการ cap แต้มและงบรวม ข้อมูลผิด การเปิดบอส ลำดับโจมตี การหลบ ความเสียหาย สกิล ติดตัว คริติคอล ดูดเลือด เจาะเกราะ โล่ พิษ การชนะ การเสมอ ขีดจำกัดตา และการไม่แก้ข้อมูลต้นฉบับ ส่วนการเปิดไฟล์จริง ปุ่ม ภาพ และหน้าจอมือถือให้ตรวจในเบราว์เซอร์ด้วย

ผลการตรวจสอบที่ทำจริงและข้อจำกัดอยู่ใน [tests/TESTING.md](tests/TESTING.md)

ถ้าหน้าเว็บไม่แสดงหลังแก้ไฟล์ ให้เปิด Developer Tools (F12) > Console ตรวจข้อความ SyntaxError มักเกิดจากลืมเครื่องหมายคำพูด จุลภาค หรือวงเล็บ หากแต้มผิดให้ดูข้อความสีแดงในรายการมอนสเตอร์
